# ترحيل Android Studio

## الحالة الحالية

تم اختبار مسار التحويل على نسخة APK أعيد بناؤها من ملفات Apktool في `app/`:

- إعادة بناء APK عبر Apktool 3.0.3: **نجحت**.
- التحويل عبر JADX 1.5.6: أنتج 48,058 ملف Java، لكنه سجّل 866 خطأ تحويل.
- الناتج ليس مصدر Kotlin/Java الأصلي، ولا يثبت قابلية البناء أو التكافؤ السلوكي.
- جزء كبير من الناتج مكتبات طرف ثالث مفككة، وليس كود التطبيق فقط.

لذلك لا يتم حذف `app/smali*` في هذه المرحلة. حذفها الآن سيزيل المصدر الوحيد القابل لإعادة بناء APK قبل وجود بديل قابل للبناء والاختبار.

## المسار القابل لإعادة الإنتاج

شغّل:

```bash
./scripts/decompile-jadx.sh
```

المتطلبات: Java 17+، Apktool 3.x، JADX 1.5.x، ومساحة مؤقتة كافية. يضع الناتج خارج Git في `.migration/work/`، ويُنشئ تقريرًا في `.migration/report.md`.

## الأسرار والاعتماديات المغلقة

كشف التحليل وجود ثوابت سرية مضمنة داخل ناتج decompilation (مفاتيح خرائط/خدمات وبيانات اعتماد أخرى). **لا تُنسخ هذه القيم إلى مشروع Android Studio ولا إلى GitHub.** يجب:

1. إلغاء المفاتيح القديمة من لوحة كل خدمة أو تدويرها إذا كانت حقيقية.
2. نقل الإعدادات العامة فقط إلى `BuildConfig` أو `local.properties` المحلي.
3. توفير بدائل محلية لمواقيت الصلاة والقبلة والقرآن المحفوظ.
4. جعل Firebase/Maps/الإعلانات/الفوترة اختيارية خلف واجهات abstraction، مع تعطيلها افتراضيًا.
5. فحص المستودع قبل كل push باستخدام `gitleaks` أو أداة مكافئة.

## معيار الانتقال من Smali

لا يُحذف `app/smali*` إلا بعد تحقق مستقل من:

- `./gradlew assembleDebug` بنجاح من مشروع Android Studio.
- تشغيل التطبيق على محاكي Android حديث.
- اختبار شاشة البداية، مواقيت الصلاة، الأذان/الإشعارات، القرآن، الأذكار، القبلة، والإعدادات.
- عدم وجود مفاتيح سرية أو endpoints خاصة في المصدر.
- مقارنة APK الجديد مع السلوك المطلوب، وليس مع مجرد نجاح البناء.

الهيكل الموجود في `android-studio/` هو نقطة بداية نظيفة قابلة للبناء، وليس ادعاءً بأنه استبدل التطبيق المفكك بالكامل.
